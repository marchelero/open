## Context
El reporte `docs/reports/2026-10-06-open-vs-agentes-comparativa.report.md` compara `open` (este pack) contra el fork `MKY/agentes` y concluye que la jugada correcta es fusionar: adoptar la infraestructura de `agentes` y conservar las skills y el MCP `anydoc` de `open`. El reporte contiene 30+ recomendaciones agrupadas en 3 bloques (§8 plan de fusión, §10.5 palancas de tokens, §11 recomendaciones novedosas). Meterlas todas en un solo PRD es inviable y arriesgado.

Este PRD cubre **solo la primera tanda**: los 4 quick-wins de menor esfuerzo y mayor retorno (medición de coste, integridad de contenido y opt-in de MCP). Los bloques grandes (router semántico, RAG cross-proyecto, fusión de instalador/CI/evals, gobernanza) quedan explícitamente diferidos a fases posteriores con sus propios PRDs.

El proyecto no tiene tests formales: la verificación se hace ejecutando los CLIs del pack (`node .opencode/bin/*.js`) y smoke-test manual.

## Objective
Cerrar los 4 quick-wins de bajo esfuerzo/alto retorno del reporte — (1) `anydoc` opt-in, (2) medidor de tokens ampliado, (3) lockfile con hash completo + verificación de drift, (4) ledger de coste por sesión — dejando el pack con una medición de gasto honesta, integridad verificable y un boot más barato, sin tocar aún la fusión de infraestructura ni los features de IA.

## Success Criteria
The work is complete when ALL of the following are true (each independently verifiable):

- [ ] **anydoc opt-in**: `opencode.json` ya no declara `anydoc` como MCP siempre-activo; `anydoc` pasa al template de MCP opcionales. `node .opencode/bin/measure-tokens.js --scenario=greeting` reporta 1 MCP activo (antes 2) y un boot ~400 tokens más barato.
- [ ] **anydoc reversible**: `setup-mcp.js activate anydoc` (o `/mcp-on anydoc`) vuelve a activarlo en `opencode.json`; `disable`/`/mcp-off` lo revierte. La skill `convert-documents-to-markdown` sigue presente y funcional.
- [ ] **medidor ampliado**: `measure-tokens.js` reporta **tres componentes** (boot = AGENTS.md + MCP + plugins; catálogo = descripciones de skills + agents; router) y un **total**, en lugar de solo boot contra una baseline hardcodeada.
- [ ] **techo absoluto**: `measure-tokens.js` compara el boot contra un techo absoluto configurable (default 2000 tokens) y marca RED al superarlo; la baseline relativa ("% de ahorro") se deriva del estado en `git HEAD`, no de una constante mágica.
- [ ] **lockfile completo**: `skills-lock.json` contiene el sha256 de **todas** las skills (`SKILL.md`) y de **todos** los agents, no solo el subconjunto actual.
- [ ] **drift detectado**: un CLI de verificación de lockfile (nombre a definir en /plan) sale con código 0 si no hay cambios, y con código ≠ 0 listando cada archivo alterado (ruta + hash esperado vs real) si hubo edición accidental o tampering. Un smoke-test que edita un skill a propósito es detectado. Un flag `--fix` re-pine los hashes tras ediciones intencionales.
- [ ] **ledger de coste**: al cerrar sesión, un hook escribe `docs/state/cost-<ISO-timestamp>.json` con, como mínimo: timestamp, agente, modelo, tokens in, tokens out y coste monetario si es computable.
- [ ] **ledger robusto**: si en una sesión no hay datos de tokens disponibles, el hook no escribe archivos corruptos (o escribe con un campo `estimated: true` explícito); cada archivo es JSON válido y queda referenciado en la memoria de sesión (`LATEST.md`).

## Assumptions
- **Tokens NO accesibles vía hook** (confirmado): `hookify.js` solo registra `tool.execute.before`. El ledger registrará estimaciones (heurística 4 bytes ≈ 1 token) marcadas `estimated: true`.
- **Cobertura del lockfile = skills + agents** (no commands ni plugins). *Validar:* confirmar en /plan el inventario exacto de `.agents/skills` y `.opencode/agents`.
- **Drift no bloquea el boot** (solo reporta con exit-code ≠ 0, gateable en CI). *Validar:* confirmar en /plan que opencode no tiene un punto de bloqueo de arranque limpio para esto.
- **Techo de boot default = 2000 tokens**, configurable. *Validar:* medir boot real tras el opt-in de `anydoc` y ajustar si queda demasiado holgado o demasiado estricto.
- **anydoc reutiliza `setup-mcp.js` + `.opencode/mcp.optional.json`** existentes; no se crea instalador nuevo. *Validar:* confirmar que el template opcional admite añadir `anydoc` sin cambios estructurales.
- **Sin implementación en este PRD**: solo requisitos. El desglose de tareas y ubicaciones de archivos nuevos corresponde a /plan.

## Users
- **Primary**: mantenedor del pack `open` — quiere saber cuánto gasta de verdad, detectar drift/tampering en skills, y pagar menos por turno.
- **Secondary**: cualquier agente/usuario del pack — se beneficia de un boot más barato y de un ledger que explica qué skill/agente sale caro.
- **Not for**: usuarios finales de apps construidas con el pack (no hay cambio de API externa).

## Constraints
- **Sin tests formales**: la verificación es con `node .opencode/bin/*.js` + smoke-test manual (editar un skill, simular una sesión).
- **Zero-deps / Node 18 stdlib**: los CLIs nuevos siguen la convención de los 15 existentes (CommonJS, sin dependencias).
- **Convenciones del pack**: artefactos en `docs/prds`, `docs/plans`, `docs/reports`, `docs/state`; PRD/plan/audit fechados con timestamp.
- **No regresión de skills**: el opt-in de `anydoc` no debe romper `convert-documents-to-markdown` ni ninguna de las 63 skills.
- **Secrets**: ninguno nuevo; el ledger no debe capturar contenido sensible, solo metadatos de coste.
