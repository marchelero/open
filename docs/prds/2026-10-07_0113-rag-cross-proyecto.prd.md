## Context
El pack `open` es un opencode starter pack zero-deps (78 skills, 67 agents, 64 commands, 21 CLIs, Node 18, CommonJS, `--json`, exit 0/1, Windows+Linux). El reporte comparativo (§11.3 #6, Top-5 por impacto/esfuerzo) propone:

> "RAG cross-proyecto compartido. Memoria **global por usuario** (lecciones de todos los proyectos), consultable desde cualquier pack instalado. Evita re-aprender lo mismo en cada repo."

Hoy el pack ya tiene **memoria, pero fragmentada y no buscable**:
- **Sesiones**: `/session-end` escribe snapshots en `docs/sessions/` + `LATEST.md` (scope proyecto, texto libre, sin índice).
- **Instintos**: `.opencode/bin/instinct.js` guarda JSON en `~/.config/opencode/instincts/` (global) y `docs/instincts/` (proyecto), con un registro `projects.json`; `/session-end` extrae 1–3 instintos. El schema es `{trigger, action, confidence, category, applications, successes}` — heurísticas, no conocimiento libre.
- **Self-improving**: el skill `self-improving` mantiene `~/self-improving/` (tiers de memoria), desconectado del resto.
- **Continuidad**: el skill `pack-governance` documenta arranque/cierre de sesión.

**Problema**: no existe un almacén **cross-proyecto** de conocimiento libre (lecciones, gotchas, decisiones, snippets de razonamiento) que sea **buscable por lenguaje natural** de forma local. Lo recuperable hoy es por nombre/trigger exacto, no por relevancia.

**Materia prima reutilizable (no reinventar)**: el router ya resolvió este tipo de problema. `.opencode/bin/lib/route-engine.js` implementa un motor **BM25 zero-dep** determinista (tokenizer con fold de diacríticos, camelCase/kebab, stopwords EN+ES, normalización de plurales/cognados; `FIELD_DEFS` con pesos; `buildIndex`/`rank`), y `.opencode/bin/lib/catalog.js` es el enumerador de catálogo. El raw material del RAG es el mismo tipo de problema (recuperar por relevancia léxica) sobre un corpus distinto (entradas de conocimiento en vez de skills/agents).

## Objective (acotar)
Entregar una **memoria de conocimiento global por usuario, buscable localmente**, que (a) persista entradas de conocimiento reutilizable entre proyectos en disco, (b) las recupere por relevancia con un motor **léxico BM25 zero-dep** reutilizado del router, y (c) sea consultable por el agente desde una superficie existente — **sin red, sin secretos y sin romper la batería**. Embeddings quedan opt-in/diferidos (mismo criterio que el router: zero-dep es el default no negociable).

## Decisión de diseño (reto central, propuesto)
**Capa única MVP: recuperación léxica BM25 zero-dep sobre un almacén JSON en disco, con CLI dedicada.** Embeddings diferidos a un PRD propio.

**Almacén (store).**
- **Ubicación recomendada**: `~/.config/opencode/knowledge/` (coherente con `~/.config/opencode/instincts/` que ya usa `instinct.js` vía `os.homedir()`, cross-platform). Alternativa: `~/.open/knowledge/` (nombre del brief). → **Q2**.
- **Override obligatorio para tests/CI**: variable de entorno (p. ej. `OPENCODE_KNOWLEDGE_HOME`) que redirige el root del store a un temp dir, para que **ni CI ni `installer-test` escriban jamás en el `home` real**.
- **Scope MVP**: **global por usuario** (cross-proyecto). Cada entrada registra el proyecto de origen; la búsqueda es cross-proyecto por defecto y filtrable por `--project`/`--tag`. Scope por-proyecto queda fuera.
- **Formato** (un archivo `knowledge.json`, portable, versionado):
  ```json
  {
    "version": 1,
    "entries": [
      {
        "id": "kb-<ts>-<rand>",
        "title": "Una frase recuperable",
        "body": "Detalle/lección/snippet de razonamiento (texto libre)",
        "tags": ["bm25", "windows"],
        "project": "<basename del cwd al crear>",
        "created": "ISO-8601",
        "updated": "ISO-8601",
        "source": "manual|session-end|import"
      }
    ]
  }
  ```
- **Indexado**: en memoria, en tiempo de query, reutilizando el **mismo tokenizer** del router; BM25 con pesos por campo análogos a `FIELD_DEFS` → `title` (alto) > `tags` (alto) > `body` (medio). Sin índice persistente en el MVP (el store es chico); regenerarlo no es necesario. Determinista y testeable.
- **Recuperación**: `search` tokeniza la query, puntúa por BM25, aplica filtros (`--tag`, `--project`) y devuelve top-N con `why` (términos matcheados), igual que `route-match.js`.

**CLI (`knowledge.js`)** — contrato estable, ASCII, `--json`, exit 0/1:
```
knowledge.js add    --title "..." --body "..." [--tags a,b] [--project X] [--source manual] [--json]
knowledge.js search "<query>" [--top N] [--tag X] [--project Y] [--json]
knowledge.js list   [--project X] [--tag Y] [--json]
knowledge.js export [--output FILE] [--json]
knowledge.js import FILE [--merge|--replace] [--json]
knowledge.js stats  [--json]
knowledge.js help
```
`--json` de search: `{ query, count, mode:"lexical", results:[{ id, title, score, matched[], tags, project }] }`. Exit `0` con resultados; `1` si no hay store/entradas o la query es inválida (convención del pack).

**Cómo lo consulta el agente.** Sin crear skills/agents/commands (rompería E11/E12/E13): se documenta e invoca desde **superficies existentes** — el skill `pack-governance` (continuidad: buscar al arrancar el task, añadir al cerrar), el skill `self-improving` (lecciones cross-proyecto) y los comandos `/session-start` y `/session-end`. El agente ejecuta `node .opencode/bin/knowledge.js search "<query>" --json` (read-only, offline). → **Q3**.

**Seguridad/privacidad.** Todo local; **cero red**; el CLI nunca imprime el contenido del store a logs externos. Guarda ligera anti-secretos en `add` (rechaza/advierte patrones comunes: `sk-`, `AKIA`, `BEGIN ... PRIVATE KEY`, `password=`, tokens largos) para no persistir credenciales. → M4.

**Reuso del motor (riesgo controlado).** Opción recomendada: extraer el núcleo BM25 a `bin/lib/bm25.js` (tokenizer + index/rank genéricos por `fieldDefs`) y que **ambos** (`route-engine.js` y `knowledge-engine.js`) lo consuman, **exigiendo que la salida del router y su gate (E16) queden byte-idénticos**. Alternativa conservadora: `knowledge-engine.js` importa `tokenize` de `route-engine.js` y aporta su propio BM25 pequeño (duplicación mínima). La elección es de `/plan`; el requisito es **no forkear el tokenizer** (una sola fuente de normalización). Como `bin/lib/*.js` no cuenta como CLI, un lib nuevo **no** cambia `counts.clis`.
